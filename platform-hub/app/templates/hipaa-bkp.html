HIPAA Compliance

This page documents approaches, not a certification. It reflects an honest audit of this platform's own architecture against the HIPAA Security Rule, plus real, sourced cost data for the self-hosting alternative. Nothing here is legal advice — the BAA question in particular needs your organization's actual counsel and Anthropic relationship, not a document like this one.

The issue no architecture fixes by itself

A Business Associate Agreement is a legal precondition, not a technical checkbox. Without one covering the specific API surface in use, sending PHI to any third-party LLM API — however well the code around it is written — has no lawful basis under HIPAA. Anthropic will sign a BAA for specifically enabled "HIPAA-ready" API configurations, but coverage is per-feature, not blanket: confirm which specific endpoints and tools your signed BAA actually covers before assuming forced tool-use (which this platform's Gateway relies on for every operation) is included.

This is an organizational decision — who owns the Anthropic relationship, whether HIPAA-ready configuration has been activated, what the signed BAA's covered-feature list actually says — not something any of the three approaches below resolves on their own.

Three Approaches

A. Managed API + Signed BAA

Anthropic's API under a signed, HIPAA-ready BAA covering the specific features in use (confirm forced tool-use is included).

  • Lowest operational burden — no model hosting, no GPU fleet
  • Best model quality/reliability for structured tool-use, which this Gateway depends on
  • Contractually dependent on the BAA being real and current
  • Per-token API cost at scale
B. Self-Hosted Open Model (Ollama)

Run an open-weight model (Llama 3.3 70B, Qwen 2.5 72B) via Ollama on a GPU VM your organization controls.

  • PHI never leaves infrastructure you control — no third-party LLM BAA needed for the model itself
  • Fixed, predictable infrastructure cost instead of per-token billing
  • You now own every other Security Rule obligation directly — the VM, its patching, its access control
  • Forced tool-use reliability must be re-validated per model — not guaranteed to match Claude's
C. Hybrid: Minimize + Managed API

Tokenize structured identifiers before they reach the Gateway, redact/limit free-text fields by intent, keep the managed API with a BAA as defense-in-depth.

  • Reduces what a BAA has to cover in the first place
  • Cheap wins available today: this platform's own retrieve_node already knows which fields an intent needs
  • Free-text fields (clinical notes, resolution notes) are hard to fully redact reliably
  • Still needs a BAA behind it — minimization is defense-in-depth, not a substitute
