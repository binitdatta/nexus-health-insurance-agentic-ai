From Zero to 10 Chatbots: Scaling One Pattern Across Departments

Common Flask application structure.

Platform context: this topic is grounded in the Nexus architecture: ten department-scoped Python Flask chatbots, one Keycloak 26 central realm, one Central LLM Gateway on port 8000, Anthropic as the external LLM provider, and one MySQL 8.x platform with department-specific data, RAG knowledge, audit logs, HITL tasks, and cost summaries.
Shared Pattern
Common Flask application structure.
Common Keycloak PKCE integration pattern.
Common JWT validation behavior.
Common Gateway client.
Common LangGraph node conventions.
Common audit logging and HITL APIs.
Department Variability
Different ports and client registrations.
Different domain tables.
Different retrieval queries and knowledge documents.
Different allowed/required fields.
Different business semantics and update rules.
Different user populations.
Why This Scales Better
Bugs fixed in the common pattern can be propagated consistently.
Security boundaries remain explicit.
Teams can explain every application using the same architecture vocabulary.
The platform can add a new department without re-inventing identity, LLM access, or audit design.
Avoid Copy-Paste Architecture
A reusable pattern is not the same as blindly duplicating code.
Extract shared libraries and contracts where they reduce divergence, while preserving department-specific policy and data boundaries.
Suggested Demonstration

Use the live platform while teaching this topic. Show the relevant department application, then trace the request through the architecture rather than explaining the concept only from slides.
