Platform Architecture

Building a 10-Department Agentic AI Platform with LangGraph

Understand why the platform uses ten department-specific chatbot applications instead of one universal chatbot.

Platform context: this topic is grounded in the Nexus architecture: ten department-scoped Python Flask chatbots, one Keycloak 26 central realm, one Central LLM Gateway on port 8000, Anthropic as the external LLM provider, and one MySQL 8.x platform with department-specific data, RAG knowledge, audit logs, HITL tasks, and cost summaries.
Learning Objectives
Understand why the platform uses ten department-specific chatbot applications instead of one universal chatbot.
Explain how LangGraph coordinates classify_intent, retrieve, synthesize, and HITL draft stages.
Understand where department-specific retrieval belongs and why the Central LLM Gateway does not perform RAG.
Trace an authenticated user request from browser to Keycloak, department chatbot, Gateway, Anthropic, and back.
Reference Architecture
Access Layer: Department users access individual Flask applications through a browser.
Identity Layer: One Keycloak 26 central realm authenticates users with OIDC Authorization Code + PKCE.
Application Layer: Ten Flask chatbots run independently on ports 5001–5010.
Shared Integration Layer: central-llm-gateway on port 8000 is the only path to Anthropic.
Data Layer: MySQL 8.x stores department domain data, knowledge_docs, logs, HITL tasks, and cost summaries.
Why LangGraph Fits
A chatbot request is not treated as a single prompt. It becomes a workflow with explicit state transitions.
Intent classification decides what business operation is being requested.
Retrieval happens inside the department chatbot against department-scoped tables and knowledge.
Synthesis sends only selected context to the Gateway for model processing.
Create/update requests can branch into a HITL draft path before any database write.
Key Architectural Principle
Centralize what should be common: identity, external LLM access, logging, governance, and cost control.
Keep business context local: department data access, terminology, validation, workflow logic, and RAG.
Suggested Demonstration

Use the live platform while teaching this topic. Show the relevant department application, then trace the request through the architecture rather than explaining the concept only from slides.
