Testing AI Agents: What to Mock and What to Run for Real

Unit-test deterministic functions without external services where possible.

Platform context: this topic is grounded in the Nexus architecture: ten department-scoped Python Flask chatbots, one Keycloak 26 central realm, one Central LLM Gateway on port 8000, Anthropic as the external LLM provider, and one MySQL 8.x platform with department-specific data, RAG knowledge, audit logs, HITL tasks, and cost summaries.
Testing Layers
Unit-test deterministic functions without external services where possible.
Use seeded MySQL data for retrieval tests.
Use real signed Keycloak tokens for critical authorization-boundary tests.
Mock the external LLM when testing application behavior that should not depend on model variability.
Run selected end-to-end tests against the real model provider to validate structured tool-use and production integration.
What to Mock
External model responses in fast unit/integration suites.
Failure modes such as timeout, malformed JSON, rate limit, and provider error.
Non-critical network dependencies where deterministic reproducibility is more important.
What to Run for Real
JWT validation using a correctly signed token and real claim structure.
Database schema and seeded data.
Cross-department negative authorization cases.
Representative structured-output/tool-use workflows before release.
Fresh installation and startup of every shipped package.
Core Principle
Mocking everything creates false confidence. Running everything against live external services creates fragile and expensive tests. Enterprise AI needs a deliberate mix.
Suggested Demonstration

Use the live platform while teaching this topic. Show the relevant department application, then trace the request through the architecture rather than explaining the concept only from slides.
